# Beast of Thornmoor

A 2D side-scrolling action RPG in the spirit of *Shadow of the Beast*: deep parallax moors beneath a
ruined castle, a horned beast-man with claws, armoured knights, spearmen, skeletons and gloom bats,
loot with random affixes, levelling, shrines and a boss at the Warden's Gate.

Everything runs in the browser from local files. There are no runtime network requests: Phaser 3 is
vendored, and every image, font and sound is generated by the scripts in `tools/` and committed.

![Thornmoor](docs/screenshot.png)

## Play

```
npm start
```

Then open http://127.0.0.1:8080/ in Chrome, Edge or Firefox. Plug in an Xbox controller (USB or
Bluetooth) and press any button so the browser exposes it; the title screen reports the detected
controller. A browser tab must have focus for the Gamepad API to deliver input.

The game is served rather than opened from `file://` because ES modules and asset loading are
blocked on the `file:` origin. Any static server works (`python3 -m http.server`, etc.).

### Controls

| Action | Xbox pad | Keyboard |
|---|---|---|
| Move | Left stick / D-pad | A / D or ← / → |
| Jump (hold for height) | A | Space / W |
| Double jump | A again in the air | Space again |
| Light attack (3-swipe combo) | X | J |
| Heavy attack: ground slam (hold to charge) | Y | K |
| Defend (hold; raise just before a hit to parry) | LT | Shift / I |
| Backstep (invulnerable hop away from the threat) | B / RT | L |
| Drink potion | RB | Q |
| Interact (shrines, chests, gates) | LB | E |
| Pause / character sheet | Start | Esc / Enter |
| Zoom out / in (seven steps, 60% to 130%, remembered) | | `-` / `+` (also numpad, `[` / `]`) |

Stamina (green) is spent by attacks, blocks and backsteps and regenerates after a short delay. Enemies
telegraph their swings: raise the guard to take a fifth of the damage, time it within a few frames of
the hit to parry (no damage, the attacker staggers and is open to a slam), or backstep clear. Armoured
knights sometimes block light attacks from the front; the slam breaks guards and staggers everything
in reach. Rumble is used on hits when the pad supports it.

**Demo mode.** "Watch the Beast (demo)" on the title (also starts by itself after 45 s idle) lets the
game play itself: the autopilot explores, fights, parries, drinks potions, lights shrines, opens chests
and passes gates. Press any key or pad button to take over mid-run.

### Progression

- Souls (XP) drop from every kill; levelling raises STR/VIT/AGI and grants points to spend in the
  pause menu.
- Gold, potions and gear drop from enemies and chests. Gear has three slots (claws, hide, charm) and
  four rarities with random affixes (damage, health, stamina, crit, speed, reach, armour, lifesteal,
  gold find). Equip from the pause menu.
- Shrines fully heal, refill potions and save a checkpoint to `localStorage`. "Continue" on the title
  resumes from the last shrine.
- Each zone's gate opens once every foe in the zone has fallen. Three zones: Thornmoor, The Hollow
  Graves and The Warden's Gate, which ends in the boss fight.

## Deployment

Pushes to `main` deploy the runtime files (`index.html`, `src/`, `vendor/`, `assets/`) to
https://blatcho.com/games/sotb/ over FTP via `.github/workflows/deploy.yml`. The workflow needs the
`FTP_SERVER`, `FTP_USERNAME` and `FTP_PASSWORD` repository secrets, and optionally the
`FTP_SERVER_DIR` (default `./`, the FTP account's home), `FTP_PROTOCOL` and `FTP_PORT` repository
variables (see the comments at the top of the workflow). `.htaccess.example` lists the MIME types the host must serve if they are not already
configured.

## Development

```
npm test              # unit tests (node:test) + headless Playwright smoke test with a fake Xbox pad
npm run test:unit
npm run test:smoke    # writes screenshots to tests/screens/
npm run assets        # regenerate backgrounds, sprites, fonts/UI and audio (Python 3, Pillow, NumPy, ffmpeg)
```

`?debug=1` on the URL draws hitboxes and an FPS counter.

### Layout

```
index.html, src/main.js      entry; scenes are registered in main.js
src/input/Input.js           keyboard + gamepad action mapping, dead-zones, edge detection, rumble
src/rig/                     runtime 2D skeletal animation (Rig.js) and keyframe clips (clips/humanoid.js)
src/entities/                Player, Enemy (AI state machine), Pickup
src/systems/                 Parallax, Combat (hitboxes), FX, Audio, Stats, Loot, Save
src/scenes/                  Boot, Title, Game, HUD, Pause, GameOver, Victory
src/data/                    zones (layouts, encounters), enemies (archetypes), items (affix tables)
assets/                      generated art, fonts, audio and rig definitions (committed)
tools/                       generators, static server, smoke test
vendor/phaser.min.js         Phaser 3.90 (MIT)
```

### Art pipeline

- `tools/gen_backgrounds.py` builds the tileable parallax layers (sky, moon, mountains, castles,
  trees, thorn hedges, ground, foreground thorns, fog) for each zone from noise and procedural
  silhouettes.
- Rendering uses Phaser's Light2D pipeline: torches, braziers, lit shrines and the moon are real
  lights, and the generators emit tangent-space normal maps for characters, props, platforms and the
  ground so they catch that light. The camera adds bloom, contrast grading and a vignette; zones have
  weather (drifting leaves, rain with lightning and thunder, falling ash) and moonlight shafts.
- `tools/gen_sprites.py` paints body parts for every character and writes the rig definitions
  (`assets/rigs/*.json`) consumed by `src/rig/Rig.js`. Characters are animated at runtime by rotating
  parts around their joints with keyframed clips, so there are no frame-by-frame sprite sheets.
- `tools/blender_props.py` models and renders the coin, soul gem, potions, chest, shrine, gravestones,
  torch, pillar and gibbet cage with Blender (`pip install bpy`, Cycles on CPU).
- `tools/gen_font.py` rasterises the bitmap fonts and HUD frames; `tools/gen_audio.py` synthesises
  all sound effects and the music loops.
